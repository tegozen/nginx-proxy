Полуавтоматический reverse-proxy: один контейнер nginx + certbot внутри образа.

Добавление субдомена
--------------------
1) Скопируйте configs/vhosts/app.vhost.example → configs/vhosts/<имя>.vhost
2) Укажите SUBDOMAIN (или SERVER_NAME=полный FQDN) и PORT (порт бэкенда).
3) В .env задайте LETSENCRYPT_EMAIL (обязателен, если для нового имени ещё нет сертификата в ./letsencrypt).
4) DNS A на IP сервера для этого FQDN.
5) docker compose up -d --build   (первый раз)   или   docker compose restart nginx

На HTTPS по умолчанию проксируются: /, /index.html, /healthz, /api/, /ws, /livekit и /livekit/ (LiveKit signaling, WebSocket, увеличенные буферы заголовка под JWT в query), /assets/, /favicon.ico, /robots.txt, файлы в корне с одним сегментом и расширением (.png, .svg, .css, .js, .json, .webmanifest и др.); остальные пути — 403. На :80 для тех же путей — редирект на HTTPS, кроме /.well-known, /ws и /livekit (как у /ws — до получения сертификата см. HTTP-only блок в entrypoint).

Лимит тела запроса задаётся на уровне vhost через CLIENT_MAX_BODY_SIZE (например, 50m) в файле *.vhost.
Если переменная не задана, остаётся стандартный лимит nginx (1m).

LightRAG (Web UI /webui, /docs и т.д.): FULL_PROXY=1 — location / на бэкенд (как раньше). LM Studio / OpenAI SSE: FULL_PROXY=2 — streaming-safe proxy (proxy-params-streaming.conf).

Ключ LIGHTRAG_API_KEY задаётся в .env сервиса LightRAG на хосте, не в этом nginx-proxy. Nginx здесь ключ не подставляет; при необходимости расширьте snippets/proxy-params.conf в образе (редко нужно).

После смены шаблона: docker compose build --no-cache && docker compose up -d.

Пример vhost для OpenClaw (страница токенов по сессиям): configs/vhosts/openclaw-usage.vhost.example → скопировать в *.vhost и задать SUBDOMAIN; см. комментарии внутри про PORT / host.docker.internal / docker network.

При старте контейнер сам:
- собирает nginx-конфиг из всех *.vhost;
- поднимает временный nginx, выпускает недостающие сертификаты Let’s Encrypt (HTTP-01);
- включает HTTPS и редирект с :80;
- по cron раз в 12 часов выполняет certbot renew и nginx reload.

Бэкенд на хосте (localhost)
---------------------------
Все сервисы слушают на машине как «localhost» — в .vhost достаточно PORT (и SUBDOMAIN/SERVER_NAME).
Прокси ходит на хост через host.docker.internal (уже в docker-compose: extra_hosts … host-gateway).
UPSTREAM_HOST не указывайте, если бэкенд на той же машине.

Важно: внутри контейнера 127.0.0.1 — это сам контейнер, не ваш ПК/сервер.
На хосте приложение должно слушать 0.0.0.0:PORT (или явный IP интерфейса), а не только 127.0.0.1:PORT,
иначе с Docker-сети запрос с host.docker.internal может не попасть в процесс.

Если когда-нибудь понадобится бэкенд в другом контейнере: docker network connect <name из compose> <container> и UPSTREAM_HOST=<имя_сервиса>.

Перезапуск vs reload
--------------------
Новые/изменённые .vhost обрабатываются только при старте entrypoint → нужен restart контейнера.
Обновление уже выданных сертификатов подхватывает cron через reload без restart.

Переменные окружения
--------------------
Скопируйте .env.example → .env и заполните email (или задайте переменные в compose).
BASE_DOMAIN — зона по умолчанию для SUBDOMAIN.
LETSENCRYPT_STAGING=1 — тестовый ACME (без rate limit).

Веб-панель управления (опционально)
------------------------------------
Опциональный сервис `control-panel` в `docker-compose.yml` (профиль `control`) даёт UI для тех же
действий, что и вручную: `git pull`, `docker compose up/restart`, перезагрузка nginx, правка `*.vhost`,
поток `docker logs`, дополнительные compose-каталоги из JSON. Ручной сценарий не меняется: файлы
`*.vhost` по-прежнему на диске, для новых/сильно изменённых vhost нужен `docker compose restart nginx`
(как выше).

Запуск на том же сервере (пример):
  docker compose --profile control build control-panel
  docker compose --profile control up -d control-panel

Порт по умолчанию только на localhost (см. `CONTROL_PANEL_BIND` в compose). Откройте
http://127.0.0.1:8081 — либо добавьте отдельный vhost HTTPS с авторизацией на уровне прокси.
Панель использует доступ к `/var/run/docker.sock` от root внутри контейнера: это эквивалентно высокому
уровню привилегий на хосте — задавайте `CONTROL_JWT_SECRET` и `CONTROL_ADMIN_PASSWORD_HASH`, не светите
порт во внешний интернет без защиты.

Переменные (`.env`): `CONTROL_JWT_SECRET`; `CONTROL_ADMIN_PASSWORD_HASH` или (только не на проде)
`CONTROL_ADMIN_PASSWORD`; при необходимости `CONTROL_COMPOSE_PROJECT`, `CONTROL_LOG_COMPOSE_PROJECTS`;
`CONTROL_EXTRA_PROJECTS_JSON` со списком `{ "id", "cwd", "compose_files?", "compose_project?" }`, где `cwd`
— абсолютный путь *внутри контейнеров панели* (дополнительные тома задаёте во `volumes:` рядом с панелью).
Каталоги прокси и vhosts: `PROXY_COMPOSE_HOST_DIR`, `VHOSTS_HOST_DIR` (пути на хосте к тому же дереву,
что монтирует nginx-proxy).

Чтобы собрать только nginx без панели: используйте `docker compose up -d nginx` без `--profile control`.

Файлы *.vhost исполняются как shell-скрипты (source): не кладите туда недоверенное содержимое.

Старый сервис certbot из прошлой версии compose: docker compose down --remove-orphans

Ошибка «Bind for 0.0.0.0:80 failed: port is already allocated»
----------------------------------------------------------------
На хосте уже занят порт 80 (или 443) — часто системный nginx/apache или другой контейнер.
Проверка: sudo ss -tlnp | grep -E ':80|:443'   и   docker ps (колонка PORTS).
Освободите 80 и 443 под этот compose: остановите лишний сервис на хосте или другой stack.
Для Let’s Encrypt HTTP-01 снаружи нужны стандартные 80/443 на этом сервере; перенос только на
8080 без прокси/редиректа с :80 ломает выдачу сертификатов.
